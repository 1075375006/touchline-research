# 足球风格库处理工具

本次流水线处理本地提供的文案；不会自行联网补抓视频，不更改原始文件。完整逐篇分析使用项目已启用的模型。前段使用 DeepSeek；其返回 HTTP 402 后，剩余批次切换到项目已启用的 responses 备用模型。回执记录实际模型，已通过校验的结果不重跑。提取使用直接结构化输出；备用模型保持其默认推理设置，未改应用全局配置。调用消耗所选接口额度；本任务没有充值或修改账户配置。

- prepare.py：按文件与文案标题分篇，保存原文、原始行号、视频ID、哈希和完全重复标记。相同视频不同版本不丢弃。
- analyze.mjs：在应用容器内读取已配置模型凭据；不输出或另存密钥。每批输入完整原文，验证ID完整性与原文锚点；跨行空白仅用于匹配，保存时还原成原始片段。不保存模型私有推理，只保存公开文本拆解。
- synthesize.mjs：逐篇分析→批次归纳→作者综合；生成角色和6项知识，检查角色长度、知识总量与引用ID。
- finalize.py：核对覆盖和引用，生成逐篇Markdown、逐篇JSONL、缺失/版本清单与总索引。
- import.mjs：对已经初始化的应用数据库导入；默认只校验，显式 --apply 才写入。只管理 corpus- 前缀的本次条目，保留原内置风格。已有记录被人工编辑时拒绝覆盖。写入前生成所涉风格/知识的回滚快照，事务写入后读回核对。

应用实际数据在 Docker 的 /app/data/touchline.sqlite；宿主机 data/touchline.sqlite 是不同的旧库，不能混用。容器的 /tmp 是 tmpfs，传文件应通过 exec 的 stdin/tar 流，不依赖 docker cp 写入此路径。

语料档案以实际存在的内容为准，不把作者主页作品数、文件名或索引条目当作已读正文。availability 是文本可用性判断，不是对原视频完整性的外部认证。风格库的足球事实不参与本场证据核验。


provider.mjs 兼容 openai 与 responses，STYLE_PROVIDER_ID 只能选择数据库里已启用的模型。recovery 保存完整小批次的有效结果，profile-parts 保存分条角色/知识输出；重启时复用。results 的同名 .error.json 是历史失败日志，存在通过校验的 .json 时以成功结果为准。

- polish.py：规范风格名称与换行，消除提示词冲突，加入原稿来源索引。
- verify-installed.mjs：只读比对11位作者的角色、名称与66个知识条目，确认与本地文件逐字一致。
- finalize.py --records-only：只归档全量逐篇结果；不宣称角色已完成。最终执行不带该参数，生成所有角色、知识文件和调用索引。
