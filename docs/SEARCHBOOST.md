# SearchBoost 搜索与第三方 API

应用 1.1.0 集成 SearchBoost **0.2.4-beta.2**，版本固定在 package.json 和 lockfile。2026-09-29 核对 npm 时，latest 标签仍为 0.2.3，beta 标签为 0.2.4-beta.2；新版 Jev 单问题、硬条件预筛和评分收敛流程来自后者。实验版本的行为可能继续变化，升级前应重新跑回归测试。

入口：**系统配置 → 搜索引擎**。所有配置和原生工具实验室只对管理员开放。保存后用于新任务；已创建任务继续使用自己的搜索参数和凭据版本。分析模型仍在独立的分析模型页面配置。

## 免费、付费与混合

| 引擎池 | 行为                                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------ |
| free   | 无搜索 API Key 也能运行。可勾选 Bing、DuckDuckGo、Yahoo、Exa-free、AnySearch。AnySearch 使用匿名配额。 |
| api    | 融合搜索仅调用已启用且有密钥的 API。全部不可用时返回错误或空结果警告，不自动改用免费引擎。             |
| hybrid | 免费与已配置 API 混合检索。AnySearch 有密钥时使用密钥配额。                                            |

原来的免费配置、SearXNG 地址和分析模型配置会保留。免费服务可能限流、验证码、网络失败或返回空结果，错误会呈现在搜索诊断和任务搜索记录中。

## 第三方搜索 API

| 服务         | 默认基础地址                        | 鉴权                        | 追加路径    |
| ------------ | ----------------------------------- | --------------------------- | ----------- |
| Tavily       | https://api.tavily.com              | 请求体 api_key              | /search     |
| Brave Search | https://api.search.brave.com/res/v1 | X-Subscription-Token        | /web/search |
| Exa          | https://api.exa.ai                  | x-api-key                   | /search     |
| AnySearch    | https://api.anysearch.com/v1        | Bearer API Key；free 池匿名 | /search     |

支持自定义基础地址、启用开关、加密保存和更换密钥。兼容网关必须实现对应服务的请求与响应格式；任意普通聊天模型地址不能作为搜索 API 使用。基础地址可含网关路径前缀，不能把密钥写进 URL 用户信息、查询参数或 fragment。

后台支持：引擎池、查询复杂度、均衡/研究/时效排序、引擎权重、时效偏好、来源域名白名单/黑名单、候选数量、最低评分、搜索深度、社区结果混入和超时。不同上游引擎原生支持的筛选条件不同，时效偏好不能替代本系统的冻结时间与原文核验。

## Jev 主动检索

Jev 是 SearchBoost 使用的专用结构化评估协议，和生成报告的语言模型是两套配置。

- TypeSafe 基础地址默认 https://api.typesafe.ai/v1，调用 /systemone，使用 jev-latest 的 typed questions/answers。
- Vercel AI Gateway 使用 https://ai-gateway.vercel.sh/v1；由上游 SDK 处理 typesafe-ai/jev 评估协议。也支持兼容 TypeSafe 的自定义网关。
- 启用 Jev、保存密钥并启用 adaptive_search 后，才能把研究任务搜索策略切换为 Jev 主动筛选。
- 每次恰好一个问题；支持 intent、最多 8 个 keywords、最多 8 条 constraints、分页和持续补搜。关注点留空时交给原生流程拆解。
- constraints 是必须满足的客观条件。研究方向用于判断阅读价值，不能把“必须同意方向”当成事实筛选条件。系统继续核验支持材料、反证、日期和原文摘录。
- Jev 原生流程按当前兼容层选择就绪引擎：free 层为免费池，api 兼容层对应 hybrid。后台的纯 api 限制针对融合搜索；Jev 可能使用当前层中其他就绪引擎，也可能调用已启用的付费 API。其内部检索和读取不受外层工具入口开关逐项限制。
- retrievalSufficient 只表示启发式检索分数达到停止条件。它不是答案正确率、事实证明或研究完整性；新版 coverageComplete 固定为 false。未知评估、失败与未达标项如实保留。
- 一次主动检索可产生多次 API 请求和 Jev 评估。研究搜索预算按入口调用次数计算，不是服务商实际计费请求总数；模型预算也不包含 Jev 内部调用。通过单次 Jev 超时和任务预算控制消耗。

## 原生工具实验室

使用已保存配置执行工具，显示完整原生响应和诊断。所有网络测试都是真实请求，有密钥的服务可能计费。

| 工具            | 已接入内容                                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------------------- |
| fused_search    | 多查询、精确引擎选择、free/api/hybrid、排序和权重、域名与日期偏好、最低评分、社区混入、结果来源和评分明细。 |
| fetch_page      | 原站正文提取、Jina 回退、focus 段落筛选、截断与 focusMiss 诊断。                                            |
| x_search        | keyword、semantic、user、thread；日期区间、作者允许/排除列表。可保存 xAI Key，留空使用原生匿名路径。        |
| adaptive_search | 单问题、意图、关注点、硬条件、Jev 主动续搜、收敛诊断、分页游标。                                            |
| search_stats    | 就绪能力、引擎状态、近期统计和缓存。就绪不等于服务已联网测试成功。                                          |
| search_layer    | show 查看；free/api 保存兼容层。api 兼容层对应 hybrid，纯付费池在上方单独选择。                             |
| clear_cache     | 清除当前配置的搜索、正文、X 和 Jev 分页内存缓存。不会删除报告或证据。                                       |

每个工具使用上游输入 Schema 校验。fused_search 工具的 max_results 为 1–10，研究配置允许候选上限 20。实验室可显式覆盖本次调用参数；未覆盖时使用已保存设置。nextCursor 只在相同配置运行时有效，超时、清缓存、服务重启或配置运行时回收后需要重新搜索。

任务自动研究可选择融合或 Jev 策略，并选择本地正文读取器或 SearchBoost fetch_page；X 通过社区混入参与融合，也可单独在实验室检索。搜索诊断随任务保存。原生工具实验室的单次操作不会自动创建研究报告。

## 凭据与运行隔离

密钥以 AES-256-GCM 加密保存在 search_credentials，配置和任务快照只保存不可猜测引用 ID。页面只返回 hasKey；留空保留，替换创建新版本，移除仅解除当前配置引用。旧任务仍保留其凭据版本，以支持可恢复研究。若要彻底吊销旧密钥，应在服务商处撤销；删除当前配置不是全历史凭据擦除。

每个配置在独立 Worker 内加载 SearchBoost，防止其进程级缓存、环境变量和凭据跨任务混用。最多 8 个配置运行时，空闲回收；长期任务数据仍保存在 SQLite。为满足上游配置文件接口，解密后的密钥短暂写入权限 0600 的运行目录，关闭时删除。Docker 的 /tmp 使用 tmpfs，不写入应用数据卷；本地开发的临时目录应由可信账户使用。

原网页读取器保持 2 MB 单响应和 22,000 字符快照上限；SearchBoost 原生读取器采用自身响应限制（当前版本 8 MiB），本应用落库仍截取至 22,000 字符。SearchBoost/Jina 路径不保证返回发布时间，日期未知时继续按现有研究审计降级。Jina 回退意味着公开页面 URL 会发送给第三方读取服务。

## 范围与验证

接入范围是 SearchBoost 的核心检索、评估、正文、X、配置与诊断能力。项目自带的 CLI 安装器、TUI 和 MCP/Pi/DSH 宿主安装配置属于其他客户端部署工作，未伪装为本应用后台按钮，也未暴露未认证的 MCP 端口。

四类搜索 API 使用隔离 HTTP 服务验证请求、响应、自定义路径、鉴权、缓存、域名过滤和密钥轮换；Jev 验证 TypeSafe 请求格式与失败降级。未提供真实搜索付费服务/Jev/xAI 密钥时，不声称这些服务已完成实网账户验收。最终构建、Docker 和浏览器记录见 VERIFICATION.md。
